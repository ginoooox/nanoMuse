# iOS same-second sync ordering

The personal app preserves relay message seq as local ordering evidence. Integer created_at, message IDs and text remain unchanged. The SQLite helper in NanoMuse/NanoMuseSyncOrdering.swift is shared by ChatStore and scripts/ios/test-sync-order.sh. It lazily creates its local metadata table, writes under a savepoint, and orders equal-second messages using relay sequence constraints and genuine task receipt parent links. Local messages without relay metadata retain their relative order inside a second. Missing evidence uses a deterministic timestamp/id fallback. Conflicting sequence, domain or causal constraints fail rather than inventing an order.

NanoMuseSync records metadata before known-message and self-echo skips, persists deferred evidence, waits for active chats before ranking, and checks page persistence before advancing its cursor. ChatStore repair uses the same canonical order so it cannot reintroduce hash order at cold read. This applies to retained and backfilled relay messages. History whose sequence was never saved and is no longer returned by the relay cannot be precisely reconstructed. Sequence describes relay acceptance order, not cross-device clock causality. A relay database reset has no protocol epoch and requires review if existing evidence conflicts.

Run `bash scripts/ios/test-sync-order.sh` on macOS. It compiles the production helper with swiftc and runs actual SQLite migration, insertion, reverse arrival, replay, metadata backfill, receipt, conflict, rollback, repair and reopen checks. The personal iOS workflow runs it before device compilation. The full ChatStore app and physical UI require separate validation. Windows SQL tests do not execute Swift. No bundle ID, signing, installation or relay protocol changes are needed.

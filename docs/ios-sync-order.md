# iOS same-second sync ordering

The personal app preserves relay message seq as local ordering evidence. Integer created_at, message IDs and text remain unchanged. The SQLite helper in NanoMuse/NanoMuseSyncOrdering.swift is shared by ChatStore and scripts/ios/test-sync-order.sh. It lazily creates its local metadata table, writes under a savepoint, and orders equal-second messages using relay sequence constraints and genuine task receipt parent links. Local messages without relay metadata retain their relative order inside a second. Missing evidence uses a deterministic timestamp/id fallback. Conflicting sequence, domain or causal constraints fail rather than inventing an order.

NanoMuseSync records metadata before known-message and self-echo skips, persists deferred evidence, waits for active chats before ranking, and checks page persistence before advancing its cursor. ChatStore repair uses the same canonical order so it cannot reintroduce hash order at cold read. This applies to retained and backfilled relay messages. History whose sequence was never saved and is no longer returned by the relay cannot be precisely reconstructed. Sequence describes relay acceptance order, not cross-device clock causality. A relay database reset has no protocol epoch and requires review if existing evidence conflicts.

Upgrade uses a one-time, metadata-only replay for old nonzero cursors. It never recreates deleted local chats/texts and never lowers the live cursor. Page identity includes account, relay and an in-memory generation captured before the request. SQLite rechecks session activity at the actual write boundary and distinguishes deferred bodies from completed writes. Metadata-only echoes have their own persistent pending-repair set. Healthy cold reads skip redundant rank rewrites.

Deleting a local session/message transactionally removes its ordering ownership. Confirmed relay wipe/re-enable controls persist a reset intent before clearing only that domain's evidence; failures and restart retry the reset before further pulls. Ordinary replay still rejects conflicting sequence. These known lifecycle resets are distinct from an unannounced external relay/database reset.

Run `bash scripts/ios/test-sync-order.sh` on macOS. It compiles the production helper with swiftc and runs actual SQLite migration, insertion, reverse arrival, replay, metadata backfill, receipt, conflict, rollback, repair, reopen, local deletion/relogin, confirmed reset, active-write deferral, metadata-only repair and scope checks. The personal iOS workflow runs it before device compilation. Helper checks are not a full MainActor/ChatStore integration or physical UI test. Windows SQL tests do not execute Swift. No bundle ID, signing, installation or relay protocol changes are needed.
